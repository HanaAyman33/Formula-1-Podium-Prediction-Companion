# Milestone 2: Formula 1 knowledge graph

`Create_kg.py` builds the graph in Neo4j from the 9 CSV files. `queries.txt` holds the 5 Cypher queries.

## Files

| File | What it is | Owner |
|---|---|---|
| `Create_kg.py` | Builds the graph: `load_entities()`, `load_results()`, `load_qualifying()`, `load_pitstops()` | Members 1–3 |
| `queries/q1.cypher` … `q5.cypher` | One query per file, each starting with its `//N. Query N` header | Query owners |
| `queries.txt` | **Submitted file**, generated by `build_queries.py` (do not edit by hand) | Member 4 |
| `check.py` | Verifies the graph: counts, types, values, relationships, duplicates | Member 4 |
| `verify_queries.py` | Runs the 5 queries and 12 unseen-style queries on Neo4j and compares each with pandas | Member 4 |
| `expected_answers.txt` | The pandas answers to all of the above, for reading without a database | Member 4 |
| `config.example.txt` | Template for `config.txt` (your own `config.txt` is git-ignored) | |

## Setup (once)

```bash
pip install -r requirements.txt
docker run -p 7474:7474 -p 7687:7687 -e NEO4J_AUTH=neo4j/yourpass neo4j:5
cp config.example.txt config.txt      # then put your password in config.txt
```

`config.txt` is read by key (`URI`, `USERNAME`, `PASSWORD`, optional `DATABASE`), so the grader's extra `DATABASE` line works and no database name is hard-coded.

## Test cycle (before every pull request)

1. Wipe the database in Neo4j Browser: `MATCH (n) DETACH DELETE n`
2. `python Create_kg.py`
3. `python check.py --rerun`: all checks must pass. `--rerun` builds the graph a second time and confirms nothing changed.
4. `python build_queries.py`: regenerates `queries.txt` from `queries/*.cypher`.
5. `python verify_queries.py`: every query must agree with pandas.

Without Neo4j, `python check.py --offline` still checks everything the loaders would send (rows, types, missing values, relationship directions, MERGE vs CREATE) against the CSVs, in about 3 seconds.

## What `check.py` verifies

- **Totals:** 51,113 nodes and 163,510 relationships. A breakdown by label and by `(start)-[:TYPE]->(end)` shows which loader is wrong if they differ.
- **Relationships:** every relationship points from the fact to the right entity (checked against the CSV foreign keys). There are no duplicates and no wrong directions.
- **Properties:**
  - Exact schema names, no helper properties.
  - Integers, floats and dates where required; times (`q1`, `duration`, `fastestLapTime`, …) are strings.
  - Every value equals the CSV value.
  - Missing values are left out, never stored as `\N` or `''`.
- **Season consistency:** `Race.year` equals the year of its `Season`. The same type checks are also asked in Cypher (`IS :: DATE`, …).
- **Constraints:** a uniqueness constraint exists on all 9 node keys.
- **Re-runs:** with `--rerun`, a second run of `Create_kg.py` leaves every count unchanged.

The expected schema is one dictionary at the top of `check.py` (`NODE_SCHEMA`, `REL_SCHEMA`). If the PDF names a property differently, fix it there **and** in the loader.
